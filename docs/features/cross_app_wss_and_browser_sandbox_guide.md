This guide documents the networking architecture, browser security sandbox constraints, and resolution pathways for connecting browser-hosted web applications (such as Microsoft Excel on the Web) to the local Kanata keyboard controller (`ws://127.0.0.1:8890`).

## 1. The Core Dilemma: Browser Security Gates

When running the add-in inside **Excel on the Web** (`https://excel.office.com`), the JavaScript code runs inside a standard browser `<iframe>` subject to global public web restrictions. Connecting to `ws://127.0.0.1:8890` is intercepted by two browser security layers:

### Gate 1: Mixed Active Content (HTTPS -> WS)
- **Rule**: Modern browsers forbid encrypted HTTPS origins from opening unencrypted WebSocket (`ws://`) connections.
- **Error**: `SecurityError: An insecure WebSocket connection may not be initiated from a page loaded over HTTPS.`
- **Requirement**: The connection **must** use secure WebSockets (`wss://`) backed by a valid TLS/SSL certificate.

### Gate 2: W3C Private Network Access (PNA)
- **Rule**: Public cloud websites are blocked from initiating direct socket connections to the user's private loopback addresses (`127.0.0.1`, `localhost`) to prevent drive-by attacks against local software and internal hardware.
- **Requirement**: The server must explicitly respond to the preflight/handshake with:
  ```http
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Private-Network: true
  ```

## 2. The 4 Resolution Pathways

### Pathway A: Zero-Dependency Local WSS Proxy (Active & Implemented)

A lightweight Node.js reverse proxy ([`wss-proxy.js`](../../scripts/wss-proxy.js)) terminates TLS on port `8891` and pipes plaintext TCP directly to Kanata on port `8890`.

- **How it Works**:
  1. Utilizes existing Windows-trusted development certificates generated by Office Add-in tools:
     - Certificate: `%USERPROFILE%\.office-addin-dev-certs\localhost.crt`
     - Private Key: `%USERPROFILE%\.office-addin-dev-certs\localhost.key`
  2. Listens on `wss://localhost:8891`.
  3. Relays raw WebSocket frames to `127.0.0.1:8890`.
- **Usage**:
  ```powershell
  # Start the proxy
  npm run wss-proxy
  ```
  In the Excel Web Taskpane settings, set **Port** to `8891`.
- **Client Auto-Detection**:
  [`WebSocketClient.ts`](../../src/websocket/client/WebSocketClient.ts#L61) automatically selects `wss://` when port `8891` is targeted.

---

### Pathway B: Cloudflare Tunnel / Public HTTPS Tunnel

Converts your local port into a public HTTPS/WSS endpoint with free, automated edge TLS.

- **How it Works**:
  ```powershell
  cloudflared tunnel --url ws://localhost:8890
  ```
  Cloudflare generates an encrypted public domain: `wss://<random-id>.trycloudflare.com`.
- **Pros**: 100% compliant with browser PNA policies; works across networks.
- **Cons**: Requires active `cloudflared` background process.

---

### Pathway C: Browser Extension Relay

Bridges web pages through a browser extension (such as [`chrome_websocket_extension`](../chrome_websocket_extension)).

- **How it Works**:
  1. The Excel Web add-in emits DOM events via `window.postMessage(...)`.
  2. The Chrome extension content script captures messages and routes them through its background service worker.
  3. The extension connects directly to `ws://127.0.0.1:8890` (extensions bypass mixed-content and PNA rules).
- **Pros**: Completely local; zero TLS/SSL certificates required.
- **Cons**: Requires the extension to be installed in the user's browser.

---

### Pathway D: Browser Developer Flag Exemption

Disables security blocks in Edge/Chrome for local development.

- **How it Works**:
  Launch browser with the following command-line switch:
  ```powershell
  msedge.exe --unsafely-treat-insecure-origin-as-secure="ws://127.0.0.1:8890"
  ```
  Or in `edge://flags`, disable **"Block insecure private network requests"**.
- **Pros**: Zero scripts or proxy layers needed.
- **Cons**: Affects developer browser session only.

## 3. Future Blueprint: Native Kanata WSS Architecture

To eliminate all external scripts (`wss-proxy.js`) and achieve a single self-contained binary, Kanata can natively support TLS termination directly in Rust:

```text
+-----------------------------------------------------------------------------------+
|                        KANATA NATIVE DUAL-PORT WSS BLUEPRINT                      |
+-----------------------------------------------------------------------------------+

     [ Client Request ]
             |
             +---> Port 8890 (Plain TCP)  ---> Standard tokio_tungstenite (ws://)
             |
             +---> Port 8891 (TLS Stream) ---> tokio_rustls TlsAcceptor   (wss://)
                                                        |
                                                        v
                                          Reads ~/.office-addin-dev-certs/
                                          Injects Access-Control-Allow-Private-Network
```

### Architectural Specifications for Kanata Core:
1. **Rust Dependencies**:
   - `tokio-rustls = "0.24"` (under feature flag `websocket_server`).
   - `rustls-pemfile = "2.0"` for certificate loading.
2. **Auto-Discovery Logic**:
   - On boot, inspect `%USERPROFILE%\.office-addin-dev-certs\localhost.crt` and `localhost.key`.
   - If present: Initialize `TlsAcceptor` and spawn secure listener on `127.0.0.1:8891`.
   - If absent: Continue running single plain listener on `127.0.0.1:8890`.
3. **PNA Header Injection**:
   In `tokio_tungstenite::accept_hdr_async`, append:
   ```rust
   resp.headers_mut().append(
       "Access-Control-Allow-Private-Network",
       HeaderValue::from_static("true"),
   );
   ```

## 4. Platform Compatibility Matrix

| Platform | Recommended Transport | Local Server Needed? | Direct Kanata Access |
| :--- | :--- | :--- | :--- |
| **Excel Desktop (Windows)** | `ws://127.0.0.1:8890` | **No** (Uses GitHub Pages) | **Yes (Native WebView2)** |
| **Excel Desktop (Mac)** | `ws://127.0.0.1:8890` | **No** (Uses GitHub Pages) | **Yes (WebKit)** |
| **Excel on the Web (Local)** | `wss://localhost:8891` | **No** (Uses `npm run wss-proxy`) | **Yes (via WSS Proxy)** |
| **Excel on the Web (Remote)** | `wss://*.trycloudflare.com` | **No** | **Yes (via Cloudflare Tunnel)** |
